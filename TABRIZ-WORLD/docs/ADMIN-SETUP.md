# راه‌اندازی مدیر TABRIZ WORLD

پنل مدیریت در مسیر `prototype/admin-dashboard.html` قرار دارد. ورود مدیر با شماره موبایل و کد یک‌بارمصرف پیامکی انجام می‌شود؛ ایمیل و رمز عبور لازم نیست. فقط حساب‌هایی که در جدول `public.tw_admins` ثبت شده‌اند می‌توانند محصولات را مدیریت کنند.

## ۱. ساخت حساب مدیر با شماره موبایل

ابتدا با شماره موبایل مدیر اصلی از یکی از این صفحه‌ها حساب بسازید و کد پیامکی را تأیید کنید:

- `prototype/account.html`
- `prototype/seller-dashboard.html`

شماره باید با قالب بین‌المللی ذخیره شده باشد؛ برای شماره ایران، مانند `+98912XXXXXXX`.

## ۲. اعطای دسترسی مدیر

در Supabase Dashboard همان پروژه، وارد SQL Editor شوید و شماره موبایل تأییدشده مدیر را در دستور زیر جایگزین کنید:

```sql
insert into public.tw_admins (user_id)
select id
from auth.users
where phone = '+98912XXXXXXX'
on conflict (user_id) do nothing;
```

اگر حساب هنوز ایجاد یا شماره آن تأیید نشده باشد، هیچ ردیفی اضافه نمی‌شود.

برای بررسی دسترسی:

```sql
select u.phone, a.user_id, a.created_at
from public.tw_admins a
join auth.users u on u.id = a.user_id;
```

برای لغو دسترسی:

```sql
delete from public.tw_admins
where user_id = (
  select id from auth.users
  where phone = '+98912XXXXXXX'
);
```

## ۳. ورود به پنل مدیریت

صفحه `prototype/admin-dashboard.html` را باز کنید، شماره موبایل را وارد کنید، کد پیامکی را تأیید کنید و وارد شوید.

- محصولات جدید در وضعیت «در انتظار بررسی» قرار می‌گیرند.
- با «تأیید و انتشار»، محصول برای بازدیدکنندگان فروشگاه سه‌بعدی قابل مشاهده می‌شود.
- با «رد محصول»، کالا از فهرست عمومی خارج می‌ماند.
- دسترسی مدیر از جدول محافظت‌شده `tw_admins` و سیاست‌های RLS بررسی می‌شود؛ هیچ کلید service-role در مرورگر قرار نگرفته است.

## نکات امنیتی

- فقط مدیر اصلی باید دستور اعطای دسترسی را در SQL Editor اجرا کند.
- برای آزمایش OTP ثابت، شماره آزمایشی و کد باید در Auth > Sign In / Providers > Phone در Supabase تنظیم شوند. کدهای تست را پیش از انتشار عمومی حذف یا منقضی کنید.
- OTP استاندارد Supabase شش‌رقمی است؛ کد پنج‌رقمی `12395` قابل استفاده مستقیم نیست. برای نمونه می‌توان کد شش‌رقمی `012395` را فقط برای یک شماره تست مشخص تنظیم کرد.
- هرگز کلید service-role یا رمز/کد تأیید را در فایل‌های GitHub یا کد مرورگر قرار ندهید.
- تصاویر در bucket عمومی هستند تا عکس کالاهای تأییدشده در فروشگاه قابل نمایش باشد؛ بنابراین هر کسی که نشانی تصویر را داشته باشد می‌تواند آن تصویر را ببیند.
- این پنل فعلاً فقط مدیریت وضعیت محصولات را انجام می‌دهد؛ تأیید هویت فروشنده، مدیریت سفارش‌ها، بازپرداخت و پرداخت بانکی هنوز در این مرحله پیاده‌سازی نشده‌اند.
