## Android build and signing
The GitHub Actions workflow builds a debug APK and, when all four repository secrets are present, a signed release APK:
- `SAVASH_KEYSTORE_BASE64`
- `SAVASH_STORE_PASSWORD`
- `SAVASH_KEY_ALIAS`
- `SAVASH_KEY_PASSWORD`

Keep the original Android signing keystore and credentials for future updates. Do not regenerate or replace the key if the buyer must install updates over an existing installation. Private signing credentials are not included in the source archive and should only be transferred securely if included in the sale agreement. Never share the GitHub password, personal access token, recovery codes, or personal account.

## Secure delivery sequence
1. Share only the 3-wave demo APK with a prospective buyer for evaluation; do not give repository access at this stage.
2. Agree in writing on price, included rights, exact files, payment milestones, and whether signing-key transfer is included.
3. Verify cleared payment before delivering the full APK/source package or transferring repository ownership.
4. If transferring the repository, review and rotate/remove seller-only Actions secrets, deploy keys, webhooks, and integrations first. Transfer only the project repository, never the seller's GitHub account.
5. Transfer any agreed signing key separately through an encrypted, private channel; never put it in a public listing, issue, chat, or source ZIP.
